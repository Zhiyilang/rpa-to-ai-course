1分水岭：RPA 与 AI 到底差在哪

先想清楚边界，才知道什么时候该用 RPA、什么时候该上 AI。

RPA 解决「重复」：流程固定、规则明确、界面/数据格式稳定。比如：每天把 3 个分店的销售表合并成一个总表、把固定格式的发票信息录入系统。

AI 解决「不确定」：输入千变万化、需要理解语义、做判断。比如：客户发来一段自由文本要你提取关键信息、一张截图里找出金额。

两者不是替代关系，是接力：RPA 负责"搬数据、点按钮"，AI 负责"看懂、判断、生成"。

判断口诀：格式固定 → RPA要理解语义 → AI两者交界 → RPA 抓取 + AI 处理

✅ 接单第一课：客户说"帮我自动化"，先问他"这事儿每次长得一样吗"。不一样的部分，就是 AI 的活。

2影刀实战：把周报/对账/爬数据自动化

三个最常见、最易成交的 RPA 场景，附最小可跑思路。

① 多表合并（周报底座）：读 N 个同结构 Excel → 按主键合并去重 → 输出总表。核心是"不靠 Excel 公式，用脚本"，避免大文件卡死。

# 伪代码（真实版见 excel-deliver-kit）
rows = []
for f in glob("分店/*.xlsx"):
    rows += read_sheet(f)          # 读
merged = dedupe_by_key(rows, "订单号")  # 去重
write_sheet(merged, "总表.xlsx")      # 写

② 双表对账：两张表按主键比对，输出"仅A/仅B/数值不一致"三类。财务、订单核对刚需。

③ 网页爬数据：影刀"网页元素"拾取 → 循环翻页抓取 → 落 Excel。注意只抓公开数据、遵守 robots。

零依赖可复现大文件不卡

✅ 我把这类工具全做成 Python 标准库版（不装 pandas/openpyxl），客户电脑"丢进去就能跑，不会本地能跑线上崩"。这是我的卖点。

3给 RPA 装大脑：GPT-4 + 函数调用

非结构化数据（文本/截图/邮件）的处理，交给 LLM；RPA 只负责拿数据和回写。

最小可跑模板：把一段自由文本 + 一个 JSON Schema 丢给模型，让它返回结构化结果，再用 RPA 回写系统。

import openai
resp = openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role":"user","content":f"从下面提取订单信息：\n{raw_text}"}],
    functions=[{                       # 定义"能调用的工具"
      "name":"save_order",
      "parameters":{"type":"object","properties":{
        "订单号":{"type":"string"},"金额":{"type":"number"},"客户":{"type":"string"}}}
    }],
)
order = resp.choices[0].message.function_call.arguments
# → 交给 RPA 回写到 ERP

三个避坑：① 永远让他返回 JSON 而不是自然语言；② 金额/日期做格式校验；③ 失败要有兜底默认，别让流程卡死。

✅ "装大脑"的本质 = RPA 当手、LLM 当脑、函数调用当接口。先把接口（Schema）定义清楚，比调模型更重要。

4从脚本到 Agent：工具调用与编排

单个脚本能干活；多个工具 + 一个"调度者"能解决多步任务 —— 这就是 Agent。

以我开源的 quorumpilot 为例：四智能体仲裁框架，把"交易前评审"拆成 4 个角色（策略/风控/合规/裁决），各自持工具，最后投票。

# Agent 编排最小骨架
planner  → 拆解任务为步骤
worker   → 每步调用一个工具（搜索/计算/读文件）
critic   → 校验每步输出是否合理
arbiter  → 汇总，决定继续 or 回退

# 关键：每个工具都是"零依赖、可断言"的函数
def tool_reconcile(a, b, key): ...   # 复用第2节的核对内核
def tool_web_search(q): ...

做 Agent 不一定要大模型框架。把"工具函数 + 一个循环 + 一个判断"写好，就是最稳的 Agent。

quorumpilot工具即函数可断言可复现

✅ 别一上来追时髦框架。先把"一个能复用的工具函数库"沉淀好（我已有 30+ 个），Agent 只是把它们编排起来。
